## 1. What was ported

ranges so the kept code is byte for byte nxnative's apart from `mtl_*` → `gfx_*` (the contract's names) and the changes listed here.

**Kept from nxnative, unchanged in behaviour:** the object model in the game's own memory (`nvn_obj.h`); textures (layouts, views, packaged data,
the flushed-range and flush-upload tables, sparse tile layouts, ZCull sizes, swizzles); samplers; programs and their shader keys (SHA-256 of the control

**The frame loop is M4's.** The acquire waits on M4's 60 Hz vsync grid unless the backend reports a display of its own (`gfx_link_active`), in which

frame statistics, NVN calls per frame, `cs_dump` (nxnative's `DM_NVN_CMDSTAT`), `gfx_set_frame`, the guest frame tick and `NXRT_EXIT_AT_PRESENT`.

Other files: `gfx/nvn_timestamp.h` (copied: counters are 614.4 MHz ticks, as nxnative writes them; M4 wrote nanoseconds), `nvn_dirty.h`, `nvn_protos.h`.

## 2. Backend selection and the null backend

**Selection** (`gfx/gfx_ops.h`, `gfx_select.c`, `gfx_api.h`, `gfx_rename.h`, `gfx_ops_table.h`): the contract functions the recording layer calls are
defined once, in `gfx_select.c`, and forward to the chosen backend's table. `gfx_api.h` lists the 82 contract functions as X-macro lines, generated by
`gen_gfx_api.py` from `gfx_backend.h` and `nvn_obj.h`; ctest `nxrt.gfx_api` fails when the contract headers change without regenerating it. A backend
defines the functions under their contract names: each of its sources starts with `#define GFX_BE <tag>` and `#include "gfx_rename.h"` (or is compiled
with `-DGFX_BE=vk -include gfx_rename.h`), which renames them to `<tag>_gfx_*`, and one source ends with `#include "gfx_ops_table.h"`, which builds
`<tag>_gfx_ops`. **For the Vulkan backend:** compile `src/nxrt/vk` that way with tag `vk`, and define `NXRT_GFX_VK` for `gfx_select.c`; `--gfx vulkan`
then picks it. `nxrt --gfx` with an unknown name stops with exit code 2. The contract headers are unchanged.

**The null backend** (`gfx/gfx_null.c`) is a GPU that draws nothing and finishes each submission at once:

- `gfx_exec` walks every handle as a replay would: `JUMP`s, `CALL`s (8 deep), and a check of each record's framing (op, size, alignment, a 16M-record
  budget against loops). A malformed list is refused with a red line and counted; the rest of the submission runs.
- **What the CPU can see takes effect**: buffer copies (`COPY_B2B`), uniform updates and buffer fills land in guest memory (inside registered pools only;
  M4 ignored them); a recorded fence gives its sync the fence the submission commits with (nxnative's rule); event writes and counter reports are
  applied at the commit. A counter record is `{time, time}` for a timestamp report and `{0, time}` otherwise, the time being the commit's guest time in
  614.4 MHz ticks (nxnative's "one time for the whole submission").
- `gfx_wait` / `gfx_wait_acq` complete at once for any committed fence, and wait on a condition variable for a fence no submission has reached.
- Pools are kept for `gfx_addr` (the program-key rule asks whether code lies in a pool); textures, registrations and programs are counted.
- `gfx_read_texels` reads the texture's storage through `nvn_texio` (with nothing drawing, the storage is the content).
- No window: `gfx_link_active` is 0, so the recording layer's display paces the game, exactly as in M4.
- `NXRT_SHADERS=1` makes it resolve every bound program through the shader cache, as the Vulkan backend will (§5): a null run then shows which
  of the game's shaders the cache has, and dumps and translates the rest.

## 4. The shader tool (`src/nxshader`)

Python, run from the source folder. `nxshader.py build <build folder>` takes an installer build folder (`shader/pkg/*.bin` and
`profile/<title>/shader_*.tsv`, with the hand-made answers merged as `nxs2.py` merges them) and, per shader:

1. **The front half of nxnative's chain** (`nxs_front.py`, from `dmsh_build.py`): the record, `job_for` with `vertex_ab`, the compute header, `tf_layout`
   and `early_fragment_tests`, the answer table's facts, the translation options (`debug`, `reduced`: nxnative's defaults). The translator is the
   installer's own Windows build of `dmsh_xlate` (`installer/host/windows/dmsh_xlate_bin`, run with `dotnet`), which writes `<key>.spv` and
   `<key>.res.json`: the SPIR-V that nxnative only ever had in a temporary folder. 64 jobs per translator process.
2. **The integer-input retranslation** (nxnative's `int_inputs`, done on the MSL there): on an SSA copy of a vertex shader (`spirv-opt --ssa-rewrite`,
   for the analysis only), an input whose every use is a bit cast to an integer is answered `uint`, and the shader is translated again. 135 of the 274
   vertex shaders, 347 inputs.
3. **The Vulkan edits** (§4.1), then **reflection** from the SPIR-V (`nxs_refl.py`, §4.3), then `spirv-val --target-env vulkan1.3`.
4. **The cache** (§4.2) and the runtime's view, `<cache>/vk/<key>.spv` and `<key>.json`.

No Metal edit is made: `spv_single_lane`, the geometry-to-compute lowering, `spirv-cross`, the MSL rewrites and metallibs are all left out.
Translation runs single-threaded by default, `--jobs` up to 4, every process at below-normal priority. Output only under `_local\` (default
`_local/nxshader/cache`).

### 4.1 The SPIR-V edits

Each is a pass with a name and a version (`nxs_spv.py`); the name, version and options of every pass that applies to a shader are in its cache key.

| edit | applies to | why | in the corpus |
|---|---|---|---:|
| `vout_init` | vertex, tessellation-evaluation and geometry shaders with user outputs | research/01 lesson 3, nxnative's `vs_init`: every user output starts as (0,0,0,1), the value an unwritten attribute reads on the hardware; Vulkan leaves it undefined (RADV gives NaN). Stores at the start of the entry function; integer outputs get the bits of 1.0f; a `Component`-decorated output its part of the vector; a geometry shader once at its start | 256 |
| `caps_trim` | modules declaring a capability they do not use | the translator declares `Float64` (and `GeometryStreams`) everywhere; Vulkan requires the device feature for every declared capability before it creates the module (Intel Arc has no `shaderFloat64`, `geometryStreams` needs `VK_EXT_transform_feedback`). Also the 16/8-bit widths, `Int64` and pixel interlock, each only when unused | 3,967 |
| `storage_fmt_caps` | modules reading or writing a storage image declared without a format | Vulkan requires `StorageImageReadWithoutFormat` / `WriteWithoutFormat` for that (Metal needed nothing); without them `spirv-val` refuses the 2 compute shaders that read such an image, and the device must report the matching features | 51 |
| variant `gl` (`depth_gl`) | the last pre-rasterisation stage | NVN's default depth convention (near = −w) on a device without `VK_EXT_depth_clip_control`: z′ = (z + w) / 2 before each return or emit, nxnative's `vs_depth`. **Pokopia sets near = 0** (`nvnDeviceSetDepthMode`, in the log), Vulkan's own convention, so it needs no variant | on request |
| variant `pad=L,…` (`pad_outputs`) | vertex-pipeline shaders | nxnative's `vs_pad`: outputs a paired fragment shader reads and this one does not write, as (0,0,0,1). Vulkan links such a pair but the input is undefined; Pokopia's profile knows no pairs, so the renderer asks per pipeline | on request |
| variant `dual` (`dual_source`) | fragment shaders writing exactly outputs 0 and 1 | nxnative's `fs_dual`: NVN's SRC1 blend factors read output 1; Vulkan reads it from Location 0 Index 1 | on request |

Variants are made with `nxshader.py variant <key> gl|dual|pad=…` (or `build --variants`) and published as `vk/<key>.<variant>.spv`.

Metal edits with **no** Vulkan counterpart: `spv_single_lane` (Vulkan has subgroups in every stage that reports them), the geometry-to-compute lowering
and `gs_slice` (Vulkan has geometry shaders), `vs_layer` (Vulkan allows layer and point size together), border colour emulation (`VK_EXT_custom_border_color`),
logic operations (Vulkan's `logicOp`), `precise::` min/max (SPIR-V's `FMin`/`FMax` follow IEEE), `c1_guard` / `cb_extent` (robust buffer access).

### 4.2 The cache

Content-addressed in two stages (`nxs_cache.py`), so a change invalidates exactly what it affects (research/01 lesson 2):

```
xlate/<d1>.spv + .res.json   d1 = sha256(translator identity, the job: code bytes, c1, answer-table facts, options)
final/<d2>.spv + .json       d2 = sha256(d1, name·version·options of each edit that applies, reflection version, validation)
vk/<key>.spv + <key>.json    the runtime's view by shader key; the json names its chain, d1, d2, the translator and its inputs
vk/CHAIN                     the chain id of the current tools: translator, front-half version, edit versions, reflection version
```

The translator's identity is the hash of its DLLs plus its embedded sources' hash (`dmsh_xlate --source-sha`, `f53384ba156e8afd`, which matches
nxnative's `dmsh_chain.lock`). A rebuilt translator misses every shader at stage 1; a new version of one edit misses at stage 2 only the shaders it
applies to (a new `vout_init`: the 276 vertex and geometry shaders); new facts for one shader miss only that shader; an entry whose chain is not
`CHAIN` is stale for the runtime (`nxshader.unit` checks all four). Writes go through a temporary file and a rename. During this work the reflection's
version went from 1 to 2 and the integer-input rule was corrected: the second corpus run reused every first translation (§6).

### 4.3 Reflection

`vk/<key>.json`, one per module (`nxs_refl.py`): for each descriptor its `set`, `binding`, Vulkan `descriptor` type and `count`, and `nvn`, what it is
in NVN terms, decoded as nxnative's `reflect()` decoded its MSL members (the same rules, from the SPIR-V names and the translator's `res.json`):
`cbuf` (uniform slot), `c1`, `drvcb` (driver segment c0 / c2), `support` (the translator's support buffer), `sbuf` with its c0 offset and `rw`,
`sbuf_ubo`, `ubo_ptr`, `tex` / `tbuf` / `img` with the slot (combined slots 0–127, separate ones from 128), `atomic`, `fetch1d`, bindless
`tex_ubo` / `samp_ubo` / `samp_id`, `tex_c2a` / `samp_c2a`, pools. A combined image sampler is one Vulkan binding, so it carries `sampler`: where its
sampler comes from (`samp_tex`: the same slot's handle; `samp`: a separate sampler slot; `samp_id`: a constant ID). Compute shaders use the Switch 2
packed driver bank (`s2_compute_layout`, nxnative's `DMSH_S2_CS` rule, which the installer builds Pokopia with). Then: the entry point and execution
model, execution modes and local size, capabilities, extensions, `uses_subgroups` (from the operations run), vertex inputs (location, component type:
the integer-input answers show here), varyings and colour outputs (location, component, type, `flat`…), builtins in and out, `drv_reads` (the c0 / c2
rows read, as nxnative recorded them), the translator's notes, the edits applied and `spirv_val`.

Corpus totals: 49,713 texture, 4,233 uniform, 3,967 support, 2,617 c1, 113 storage-buffer, 56 image, 37 driver-segment and 25 texel-buffer bindings;
no binding the rules could not place (`?`).

## 5. Run-time shaders

**Design.** The run-time key is the program's shader key (`prog_key`, computed lazily for Switch 2 blocks, as nxnative does at first draw). A backend
asks `nxs_resolve(program, stage)` (`gfx/nxs_rt.c`) when it builds a pipeline. A hit returns the cached SPIR-V and its reflection. A miss is
**never silent**:

1. a red log line, once per key, and a counter;
2. the program stage is dumped exactly as nxnative's replay dumps it with `DM_NVN_SHDUMP` (`<key>.ctl`, the 0x880-byte control section, a Switch 2
   block being its 0xe0 bytes; `<key>.code`, control +0x44 bytes of the code area). The recording layer keeps a copy of every control section while a
   cache is configured, since the game may free its own;
3. `nxshader.py ondemand --dump <dir> --key <key>` is started for it (one at a time, below-normal priority, no window; its output in `<dump>/<key>.log`):
   the installer's own steps in a scratch folder (`s2_dumps.py`, `lower_corpus.py` running `ampere-lower`, `s2_pkg.py`), then the chain above into the
   same cache;
4. the key is looked for again twice a second; when it appears (made by the current chain) the next resolve returns it, with a log line.

Configuration: `NXRT_SHADER_CACHE` (default `<repo>/_local/nxshader/cache`), `NXRT_SHADER_DUMP`, `NXRT_SHADER_TOOL` (`off` = dump and log only),
`NXRT_SHADER_BUILD` (an installer build folder whose answer table to use). The 154 known run-time keys of 2.0.1 are all in its build folder already
(the installer's `nxs2.py refresh` added the phone's dumps), so `nxshader.py build` translates them up front; the on-demand path is for the next ones.

**Implemented and checked:** the lookup, the dump, the request queue and the pickup (`nxrt.nvn_rec`: a missing stage is dumped in the right format and
counted; a stale entry is refused; the current one is found), the tool side on all 364 recorded Mac dumps, and a live title run (§6).
**Not yet:** a prewarm at start (the backend can call `nxs_get` for every known key); the variants by pipeline state on demand.

## 7. What the replay (M5-C) needs

From the recording layer:

- **The records.** `gfx_exec(handle)` per submitted handle, with `gfx_exec_rest` telling which handles follow. Follow `JUMP`s and `CALL`s; read
  compact records with `vbuf_rec`, `bind_buf_rec`, `bind_rec`, `draw_rec`, `draw_idx_rec` (nvn_obj.h); texture records carry snapshots of the texture
  objects after the record struct (read those, not the pointers); `p_bind_handles.defer` means read the handles at `src` at replay time; texture and
  sampler IDs already include the descriptor-pool bases (`nvn_dpool_base` gives a pool's base).
- **CPU-visible effects** at completion: `OP_FENCE_SYNC` sets the sync's fence to the one the submission will commit with and `fenced = 1`; event writes
  and counter reports post to completion (counter records as in §2, 614.4 MHz ticks); `gfx_wait` returns when the GPU has completed up to a fence.
- **Present**: `gfx_present` returns a ticket at once, `gfx_present_wait` waits until that present has been handed to the GPU; report the real
  display through `gfx_link_active` / `gfx_link_wait_tick` and the recording layer paces acquires by it instead of its own 60 Hz grid.
- **Resources**: `gfx_pool_add` / `gfx_addr` (guest address = GPU address), `gfx_tex_init` / `gfx_tex_release` by serial, `gfx_reg_tex` /
  `gfx_reg_image` / `gfx_reg_samp` by table ID, `gfx_tex_cpu_written` after `WriteTexels` (upload from the storage), `gfx_read_texels`
  (the storage through `nvn_texio`, or a GPU readback for textures the GPU wrote). Uploads read the block-linear storage with `nvn_texio` / `s2tex`.
  Dirty tracking: `gfx/nvn_dirty.c` (the recording layer registers every physical pool with it).
- **Shaders**: `nxs_resolve(prog, stage)` at pipeline creation; the reflection's bindings give the descriptor layout (everything is in set 0) and
  what fills each binding: uniform slots and storage slots from the recorded binds, textures and samplers from the bound handles through the
  registered tables, the driver segments c0 / c2 filled per `dmsh_abi.h` (`DMSH_DRV_SIZE`, the handle tables, the compute shaders' packed layout in
  `s2_compute_layout`), `c1` from the reflection's translator data, and the **support buffer** in Ryujinx's layout (render scale, viewport size,
  fragment flags).
- **Device features** the corpus needs: `shaderDrawParameters` (all 274 vertex shaders declare `DrawParameters`), the subgroup operations the
  reflection reports (ballot, vote, shuffle; check `subgroupSupportedStages`), `shaderStorageImageReadWithoutFormat` / `WriteWithoutFormat`,
  `shaderImageGatherExtended`, texel buffers, geometry shaders (2), descriptor indexing for the texture arrays. Vertex attribute formats must match the
  input types in the reflection (integer inputs are `uint`).
- **State the shaders do not cover yet**, each a variant to add the way nxnative added an MSL entry point: the alpha test (`dmsh_alpha.py`; push the
  function and reference), integer colour targets when a pixel shader declares float outputs (`fs_uint`), the base instance read from c0 + 0x644 for
  indirect draws (`vs_base_instance`; 8 of Pokopia's vertex shaders read that row: fill it per draw, and for an indirect draw rewrite the read to
  `BaseInstance`), padding outputs for a pair (`pad=` exists), dual-source blending (`dual` exists). The translator was asked for an
  upper-left origin and no Y flip, as nxnative's Metal build: the viewport must match.
