Native builds of games you own

Kiln

Put your own game files in. Get a native build out. No emulator in between: the game's own code runs on your CPU and its graphics go through your GPU's own API.

How a build works

You give Kiln your own dump. A long build step takes the game apart and translates it once, so that playing never stalls on it.

Mario Kart World on the Steam Deck: speed

Measured in a race on the Deck (RADV, Vulkan). Handheld mode renders at 1920×1080 instead of 2560×1440 and halves the GPU work, but the frame rate barely moves: the bottleneck is the CPU thread that replays the game's draw commands through Vulkan, about 3,000 draws a frame. That thread is what the current work speeds up.

Development log

6 Nov 2026

Menus and the world map render

The game boots, sound plays, every 2D screen is right. As soon as a race starts, the screen goes black.

7–8 Nov

Hunting in the dark

Only the HUD survives. Hundreds of render-target dumps, many theories ruled out (ASTC, the froxel fog volume, dynamic write masks). The first glimpse: the track's outline in the light buffer, so the geometry is drawn and something removes it later.

9 Nov, morning

Tools we can trust

Pass images were taken before their submission had run, so several conclusions were wrong. They are now copied inside the command stream and written once the GPU is done. An old EQUAL→LEQUAL depth hack turned out to do harm.

51be916 in-stream pass images
9 Nov, 17:17

The black screen: timestamps in the counter field

The game uses conditional rendering ("clear if this counter is not 0") followed by a timestamp report to the same address, so the clear runs once a frame. Kiln wrote the timestamp into the counter field, and only at completion, so the finished scene was cleared again. The counter is now written as 0 immediately. The whole track appears.

5877bd8 timestamp reports: counter 0, written at once
9 Nov

Lost draws into storage textures

Colour-grading tables, the 6144×6144 terrain atlas and the final upscale target were created without render-target use, so everything drawn into them vanished.

394a6fb storage-class textures may be render targets
9 Nov, 19:10

Green and pink speckles: one wrong byte select

The fog pass packs two colour channels as half-floats in one register and unpacks the high one with I2F.U16.H1. The Ampere→Maxwell lowering passed the half-word selector on as a byte selector, so the shader read bits 8–23 instead of 16–31 and mixed two channels. One line fixed it.

9329a92 ampere-lower: I2F.U16 high half-word selects Maxwell byte 2
9 Nov, evening

Speed and the remaining picture faults

Profiling shows the replay thread is the limit. First fixes: a per-draw shader lookup that formatted strings on every draw, and descriptor sets that are now reused when a draw binds what an earlier one did. Still open: a pink cast on distant materials, flicker on dithered fades, memory growth over long sessions.

Your copy, your dump, your build

This repository contains tools only. It never contains any part of a game: no code, no data, no shaders in any form, no screenshots of game content. Everything that comes from a game is produced on your machine, from your own dump, and stays in your build folder. Kiln is an independent fan project with no affiliation with Nintendo or any game's publisher.

Kiln is a fork of the Pokopia native builder by xFractals and builds on nxnative, Ryujinx and Eden-NS2. Source and licences: see the repository.
